# 11 - JTBD + GSD Methodology

## Objetivo

Usar Jobs to be Done para manter o foco no resultado do usuario e GSD para garantir que cada ciclo termine com algo validado, documentado e pronto para o proximo passo.

## Formato de trabalho

Antes de implementar uma etapa, escreva mentalmente ou no status:

- Job: qual progresso real o usuario quer obter.
- Outcome: como saberemos que funcionou.
- Next action: menor incremento util.
- Evidence: validacao que prova o resultado.
- Status update: o que deve ser registrado no roadmap ao final.

## Regra GSD

Cada ciclo deve terminar com:

- incremento pequeno e completo;
- validacao proporcional ao risco;
- docs atualizados;
- proxima acao clara;
- nenhuma dependencia implicita escondida na conversa.

## Template de ciclo

Use este formato em `12-execution-roadmap.md` ao finalizar trabalho:

```md
### YYYY-MM-DD - <titulo curto>

Status: done | partial | blocked
Job: ...
Outcome entregue: ...
Validacao: ...
Decisoes: ...
Arquivos/docs impactados: ...
Proxima acao: ...
```

## Como atualizar este doc

Atualize apenas se a metodologia operacional mudar. Mudancas de progresso pertencem ao roadmap, nao a este documento.
